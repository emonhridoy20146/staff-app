# 06 — Data Model (staff-app local SQLite via drift, encrypted)

Server model: `field-api/docs/06-data-model.md`. Local tables mirror the **user's scope only**. All money in poisha (INTEGER). Times stored as INTEGER epoch ms UTC; business dates as TEXT `YYYY-MM-DD` (Dhaka).

## 1. Common columns
`client_id TEXT` (UUIDv7, PK for locally created rows) · `server_id TEXT NULL` · `sync_state TEXT` (`synced|queued|sending|conflict|failed`) · `updated_at INTEGER` · `server_version INTEGER NULL`.

## 3. Migrations
Current `schemaVersion` = **15**. v14 → v15 (contract 1.38.0, FR-M-063): create table `map_places` (only when missing); nothing else moves. v13 → v14 (contract 1.35.0, FR-M-059): add `collections.deposit_id`, `collections.deposited_at`, `deposits.collection_count`, `non_cash_poisha`, `non_cash_count`, `failure_code` (nullable, added only when missing; the next pull fills them; nothing unsynced is touched, no new snapshot). v11/v12 → v13 (contracts 1.31.0-1.33.0, FR-M-057/058): one idempotent step that creates `colleague_activities` (with `voided_kind`) if missing and adds `promises.created_by_name` and `collections.previous_amount_poisha`, `voided_kind`, `voided_by_name`, `voided_reason` where missing (schema 12 changed while it was being built, so a phone that ran such a build is at 12 with columns missing; nothing existing is touched; the server's resync floor makes the phone take one fresh snapshot, which only upserts). v10 → v11: add `schedule_lines.paid_on`, `days_late` (0), `missed` (false), `payments_json` (contract 1.14.0 fields; the next pull fills them; FR-M-054). v9 → v10 (0.13.x, contract 1.25.0): add `attendance_day.overtime_min` and `attendance_day.over_break_min` (default 0; the next pull of the day fills them; nothing else moves, no new snapshot). v8 → v9 (0.12.0, contract 1.20.0): create `tasks` (a new table only; no new snapshot is forced, tasks arrive on the change feed once `module.tasks` is on). v7 → v8 (0.11.0, contract 1.19.0): add the branch and assignee-name columns on `customers` and set `sync_state.bootstrap_done = 0`, so the next sync takes a fresh snapshot of the whole branch (snapshot pages only upsert). v6 → v7 (0.10.0, contract 1.13.0): add the ERP-shape columns on `customers`, `plans`, `schedule_lines` and `erp_payments` listed above (all nullable or with defaults: `kind` = `installment`, amounts 0, flags false; the next pull fills them). v5 → v6 (0.9.0): create `broadcasts`; add `contact_attempts.target` (default `customer`; a v1 file gets the column when the v2 step creates the table). v4 → v5 (0.8.0): add `location_proposals.method` (default `gps`, so queued old proposals keep their body) and `location_proposals.device_geo_json`. v3 → v4 (0.6.0): create `cowork_sessions`; add `visits.user_id`, `visits.co_work_session_id`, `visits.co_work_participant_ids_json`. v2 → v3 (0.3.0): add `location_proposals.decision_reason`. v1 → v2 (0.2.0): create `contact_attempts`, add index `idx_location_queue_t`. Tested in `test/core/migration_test.dart` (outbox rows survive). `bat`/`chg` in `location_queue` stay null until a battery plugin is added.

drift `schemaVersion` integer; each feature contributes `MigrationStep`s registered in `core/db/migrations`; every version upgrade is tested from **every** previous released schema (`drift_dev schema dump` + `verifySchema` tests). Never drop a table containing `outbox`/`collections` rows without migrating data.

## 4. Data lifecycle on device
- Out-of-scope customers (tombstones) deleted after their pending mutations are done.
- Own collections kept 60 days, visits/notes 30 days beyond scope.
- Logout: requires empty outbox (or explicit manager-forced logout) → wipe DB file + media dir + secure storage tokens.
- 5 failed PINs → lock; requires online password login of the **same** user to unlock (data kept encrypted).

**0.13.1 (FR-M-037), no schema change:** `customers.phones_json` is a JSON array. An ERP number is a plain string (as before); a number added in the field is `{ "n": "01XXXXXXXXX", "s": "f", "l": label?, "p": true? }` where `p` marks one saved on this phone and not yet on the server. Read through `decodePhones` (`customers/src/domain/phones.dart`), never by hand.
